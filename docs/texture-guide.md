# AshVehicles テクスチャの書き方

AshVehicles（Minecraft 1.21.1 / NeoForge / GeckoLib 4.9.2 の車両・航空機 MOD）の機体テクスチャを描く人と AI のための手引き。
この1枚だけ読めば作業できるように書いてある。数値は 2026-11-04 に同梱ファイルとコードで確かめたもの。

- 前半（1〜3 章）は**ゲームが読む規則**。外すと表示が壊れる
- 中盤（4 章）は**画風**。外すと「同梱機らしくない」と差し戻される
- 後半（5〜8 章）は**手順・失敗例・合格基準**

---

## 0. 最初に守ること（要約）

1. 機体・車両・兵装のテクスチャは **`.bbmodel` に埋め込んだ PNG 1 枚**。別の png を置くのではない
2. アルファは **0 か 255 だけ**。半透明は描けない（cutout で捨てられるか、不透明になる）
3. 画風は**ドット絵のパネル書き込み**。写実的なグラデーション・汚し・まだらは描かない
4. 色は**区画ごとに 1 色**。線は 1 画素で、構造（平面形の縁・胴体の縦線・翼の区切り）に沿わせる。**左右対称**
5. キャノピーのガラスは**アルファ 0 で抜いて**、内装を見せる
6. 文字と標識は**ドット文字**で、縁をぼかさない。**鏡文字にしない**
7. テクスチャは UV の地図（ばらばらの面の寄せ集め）なので、**画像生成 AI の絵を貼っても合わない**。面ごとに世界座標から色を決めて塗る

## 1. テクスチャはどこにあるか

| 対象 | 置き場所 | 形式 | 備考 |
|---|---|---|---|
| 機体・車両 | `src/main/resources/assets/ashvehicles/bbmodel/entity/<id>.bbmodel` | 埋め込み PNG | 同梱 68 模型。**これが唯一の源**（geo.json・png・animation.json は 2026-11-03 に削除済み） |
| 兵装・ラック・装備 | `…/bbmodel/weapon/` `rack/` `equipment/` の `<id>.bbmodel` | 埋め込み PNG | 24 / 6 / 4 模型 |

| 素材アイテム | `…/textures/item/*.png` | 16×16（40 枚）・32×32（17 枚） | 手描き |
| 兵装のアイテム | 不要 | — | インベントリでは模型そのものを立体で描く。`<id>_item.png` を置いても生成パックに上書きされる |

## 2. ゲームが読む規則（外すと壊れる）

### 2.1 bbmodel の中身

- `textures[i].source` が `data:image/png;base64,…` の埋め込み PNG。ゲームは**面がいちばん多く使っている 1 枚**を `DynamicTexture` として登録する（GeckoLib は 1 模型 1 テクスチャ）。2 枚目以降は警告が出て使われない → **1 枚にまとめる**
- 外部ファイル参照だけで埋め込みが無いテクスチャは登録されない
- `"texture": null` の面は描かれない

### 2.2 UV の単位と画像の大きさ

- UV 座標を数える寸法は、テクスチャの **`uv_width` / `uv_height`**。無ければプロジェクトの `resolution`
- **画像の画素数は UV 寸法と違ってよい**（UV は比率で引かれる）。例: Eurofighter は UV 512 に画像 4096（1 UV 単位 = 8 画素）、Leopard 2 は UV 1024 に画像 2048。整数倍にしておくと画素の境目が UV に揃う（TOS の UV 208 に画像 512 のような半端は避ける）
- 画像は 2 の累乗（128〜4096。2048×1024 のような長方形も可）。同梱は全部そう
- 目安: 牽引砲など小さい物 128〜256、戦車・装甲車 512〜1024、戦闘機 1024、爆撃機・大型機 2048

### 2.3 面ごとの UV と box UV

- 新しく描くなら **面ごとの UV（per-face, `box_uv: false`）** にする
- 同梱の古い模型は**要素ごとに `box_uv: true`** のものが多い（5303 要素。F-14・A-10・F-4・F-15 など）。**box UV の要素では、ゲームは `uv_offset` から GeckoLib に UV を組ませ、面の `uv` は読まない**。スクリプトで既存の UV に塗るときは、先に全部を面ごとの UV へ組み直す（5.3）
- `mirror_uv` は box UV のときだけ効く。意味は 2 つ（east/west の面の入れ替え ＋ UV の u を反転しない）で、片方だけ真似ると模様だけが裏返る
- 面の `rotation`（0/90/180/270）はゲームが読む（`uv_rotation`）。同梱では TOS（758 面）と Eurofighter（4 面）だけが使う。自分で UV を組むときは使わない

### 2.4 面の向きと UV の対応（Blockbench の Java 慣習）

`uv = [u1, v1, u2, v2]`。v は画像の上から下。キューブの `from = (x1,y1,z1)`、`to = (x2,y2,z2)` のとき、
面の上の割合 t（u 方向, 0 が u1）・s（v 方向, 0 が v1）にある点は:

| 面 | 法線 | u が進む向き | v が進む向き | 点 |
|---|---|---|---|---|
| north | −z | x2 → x1 | y2 → y1 | (x2 − t·dx, y2 − s·dy, z1) |
| south | +z | x1 → x2 | y2 → y1 | (x1 + t·dx, y2 − s·dy, z2) |
| east | +x | z2 → z1 | y2 → y1 | (x2, y2 − s·dy, z2 − t·dz) |
| west | −x | z1 → z2 | y2 → y1 | (x1, y2 − s·dy, z1 + t·dz) |
| up | +y | x1 → x2 | z1 → z2 | (x1 + t·dx, y2, z1 + s·dz) |
| down | −y | x1 → x2 | z2 → z1 | (x1 + t·dx, y1, z2 − s·dz) |

`u1 > u2` なら左右反転して貼られる（その面の t は u1 側から数える）。画素 (X, Y) の中心は
`t = (X + 0.5 − u1)/(u2 − u1)`, `s = (Y + 0.5 − v1)/(v2 − v1)`。画像が UV の k 倍なら UV を k 倍して数える。

### 2.5 座標系

- 回転は**要素の回転 → 親グループの回転を内側から外側へ**の順に、それぞれ自分の `origin` まわりに掛ける。行列は `Rz·Ry·Rx`（度、符号はファイルのまま。geo.json 用の符号反転は bbmodel には要らない）
- **bbmodel の機体: 機首が −z、上が +y、機体の右（パイロットから見て右）が +x**（右手系）。geo.json は x の符号が逆なので混同しない
- 地上車両の一部（Leopard 2・Pantsir）は根のグループ自体が半回転している。**向きは名前でなく実際の形で確かめる**
- **左右の名前は当てにならない**（`LGear` が右にある模型が半分）。左右は x の符号で判断する

### 2.6 描画のされ方

- 通常は `RenderType.entityCutoutNoCull`: **アルファ 0.1 未満の画素は捨てられ、それ以上は不透明**として描かれる。半透明のガラスは描けない
- **NoCull なので面は裏からも見える**。胴体の殻の内側（キャノピー越しに見える面）にも外板の柄が出る → 内側を向く面はコックピットの色で塗る（4.6）
- 遠景のゴーストだけは半透明・裏面カリングで描かれる（テクスチャ側で気にすることは無い）
- ミップマップで透明部分と混ざって透けることがあるので、**シートに半端なアルファを入れない**

### 2.7 解像度

- 外板は**模型の 1 単位 = 1 画素**（1 単位はブロックの 1/16 に `model.scale` を掛けたもの。実機でおよそ 1 画素 ≈ 5 cm）
- コックピットの内装は **4 画素/単位**、ガラスと枠は 2 画素/単位
- 回したキューブ（後退翼・傾いた尾翼）の上に標識を載せる部品だけ 2 画素/単位にしてよい（4.4）

## 3. やってはいけないこと

- 写実的な陰影・グラデーション・汚し・パネルごとの色むら・まだら
- 半透明（アルファ 1〜254）。ガラスもアルファ 0 か 255
- 画像生成 AI の絵や写真をシートに直接貼る（UV の島に合わない）。参考資料としてだけ使う
- 毎行ずらした継ぎ目、乱数の格子のパネル割り（ノイズに見える）
- 斜めの縁に平行線を 2 本以上（ガタガタに見える）
- 標識をぼかす・アンチエイリアスする（デカールは閾値で抜く）
- 文字を鏡文字にする
- ガラス板の縁を全部塗る（青い籠に見える）
- 同じ面に重なった古いキューブを残す（格子がずれて Z ファイティングする）

## 4. 画風（ハウススタイル）

### 4.1 原則: ドット絵のパネル

Minecraft の解像度では滑らかな陰影はぼやけるだけで、**1 画素で決まる書き込み**（パネルの線・点検口・ステンシル）の方が読める。
手本は同梱機そのもの（F/A-18E・F-22・Su-57・Su-30SM・F-104G）。新しい機体はこれに揃える。

### 4.2 数字で見た同梱機（2026-11-04 実測、不透明画素について）

| 模型 | シート | 色数 | 上位 8 色の占有 | 上位 32 色の占有 | 隣と色が変わる割合 | 変わるときの差（RGB 差の和） |
|---|---|---|---|---|---|---|
| F/A-18E | 1024 | 78 | 88.0% | 98.5% | 13.7% | 155 |
| F-22 | 1024 | 101 | 86.6% | 97.8% | 10.1% | 134 |
| Su-57 | 1024 | 625 | 85.8% | 94.2% | 13.3% | 149 |
| Su-30SM（内装 4 画素/単位） | 1024 | 131 | 66.0% | 92.2% | 25.0% | 91 |
| F-104G（無塗装の金属） | 1024 | 89 | 73.8% | 93.6% | 22.0% | 110 |
| M3A3 Bradley | 512 | 93 | 91.0% | 98.1% | 15.8% | 66 |
| BMPT | 512 | 26 | 98.8% | 100% | 13.6% | 46 |
| Grim-2 | 512 | 9 | 100% | 100% | 19.6% | 29 |

差し戻された最初の版は **450〜700 色・上位 32 色で 51〜76%** だった。見分けるのは色数と上位 32 色の占有で、
**上位 32 色で 90% 以上**が合格の目安（測り方は 7 章）。色数そのものは幅がある（Su-57 は 625 色でも上位 32 色で 94%）。
航空機は線の明暗差が大きく（90〜155）、地上車両は小さい（30〜70）。

### 4.3 航空機の外板

- **色は区画ごとに 1 色**。上面と下面で別の 1 色（下面は少し明るい）
- **平面形の縁**（上から見た翼・尾翼・胴体の輪郭）に明るい 1 画素の帯。縁の色と 50% 混ぜる
- その **3 画素内側に暗い線を 1 本**（前縁フラップの線）。後退翼・デルタの斜めの縁ではこれ以上並べない
- **主翼のスパン方向の区切り**: 暗い線＋その隣に明るい線の二重線を数本
- **胴体**: 背骨の両脇に縦の線を数本、決まった位置に横の区切り（ステーション）。区切りは暗＋明の 2 画素
- **リベット**: まっすぐな線の 2〜3 画素脇に、3 画素おきの点列
- **舵面**（フラップ・エルロン・ラダー）は自分の形で縁取る（外周を暗く、1 画素内側を明るく）
- **パネル割りは左右対称で機体に沿う**。区画の大きさは 18〜22 単位おきが目安
- **小物は少なく**: 枠付きの点検口（左上の辺が明るく右下が暗い）・「＋」「×」・小さな暗い四角・縞の通気口・小さな明るい板
- 上面には**赤い破線の歩行帯**（3 画素周期で 2 つ塗って 1 つ空ける）と角の「×」
- 迷彩は大きな形で、境目は 2〜3 画素単位の階段
- ノズルは暗い地に灰色のブロックの列（縦の縞）
- 無塗装の後部（エンジンの熱で焼けた金属）は平らな帯 2 本と輪の線

明暗は掛け算で付ける: 暗い線 ×0.80、明るい線 ×1.08〜1.13、リベット ×0.88、点検口の暗い辺 ×0.80。

### 4.4 標識・文字

- 文字は **3×5 のドット文字**（字間 1 列）。機番など大きい物は **2 倍**、白か黒の 1 画素の縁（8 近傍に太らせる）
- ぼかさない。アルファは 0/255 の閾値で抜く
- **平らな面に置く**。斜めのスライスが重なる機首などでは崩れる
- **鏡文字にしない**: デカールを面に投影するとき、画像の右方向 r を「上方向 u × 外向き法線 n」にすると、その面を外から見て正しく読める
  - 胴体の右側（n = +x、u = +y）→ r = −z（機首へ向かって読む）
  - 胴体の左側（n = −x）→ r = +z
  - 主翼の上面（n = +y、上辺を前縁へ u = −z）→ r = +x
  - 主翼の下面（n = −y、u = −z）→ r = −x
- **回したキューブの上の文字は崩れる**（テクセルの格子がキューブと一緒に回っている）。直し方:
  - 文字をそのキューブと同じだけ傾けて置く（13 度傾いた尾翼なら u = (0, cos13°, sin13°)）
  - 形の標識（星・円）はその部品だけ 2 画素/単位にする
  - 標識はなるべく回っていない板の上に寄せる
- 重なったキューブ（前縁の帯・アンテナの張り出し）の上は格子が 2 枚混ざるので避ける
- 色の例: 赤 `#C8202A`、白 `#F2F2EE`、黒 `#1E1E1E`、米軍の青 `#1F3F86`・赤 `#B22234`。低視認塗装は地より明るい灰 `#8C939A` と中間の灰 `#6C737A` だけで描く

### 4.5 キャノピー

- **ガラスはアルファ 0**。描くのは反射の筋（`#E9F4FA`、斜めの細い線を少し）と、ガラス板の薄い側面（厚さ 3 画素以下の面は不透明の淡い水色 `#CFE3EE`）だけ
- 反射の筋は外を向く面にだけ、1 枚に 1 本程度
- 枠は**風防のアーチ・キャノピー後端・下縁（シル）だけ**。各ガラス板の縁を全部塗ると青い籠に見える
- 枠の色は外板の色を少し暗くしたもの、または暗い灰（`#3E4349`）に淡い水色の縁

### 4.6 コックピット（4 画素/単位）

外板の UV には触らず、内装のグループの面だけをシートの空きへ 4 画素/単位で詰め直して描く。

- 浴槽（コックピットの壁）: 米 `#4F5356`／旧ソ連 `#3E9AA0`（ソ連機は青緑）。縁は明るく
- 計器盤: 灰に面取り（左上を ×1.25、右下を ×0.72）。パイロットに向く面に丸い計器の列
- MFD: 紺 `#14203A` の画面に段々の斜め・シアン `#3FB7C9` の十字。周りにクリーム `#CFCBB8` などのボタン
- サイドコンソール: 2 画素のボタンの列（灰が主、ときどきパステルの赤と緑）
- 座席: オリーブ `#5C5C3B` と `#4D4D30` の 4 画素の市松、縁は暗く。射出ハンドルは黄黒
- グレアシールドは黒に HUD の灰の帯。HUD のガラスは抜いて、緑 `#7FE08A` の線を 1 本
- 胴体の殻の内側を向く面（キャノピー越しに見える）は浴槽の色で塗る

## 5. 作業手順

スクリプトで描く流れ。Blockbench で手で描く場合も規則と画風は同じ。

### 5.1 道具

`drafts/paint_lib/`（**git 管理外**。ユーザーの作業コピーにだけある）:

| ファイル | 中身 |
|---|---|
| `bb.py` | bbmodel の読み書き（`Model`）、テクセル → 世界座標（`face_point` `to_world`）、点群の確認用レンダラ（`render` `sheet`） |
| `house.py` | UV の組み直し（`layout`）、材質ごとの密度（`density_for`）、ドット文字（`pixel_text`）、国籍標識（`soviet_star` `us_insignia`）、塗りの基底クラス `Painter` |
| `house2.py` | 4.3 の癖を実装した `Painter`（平面形の距離マップから縁の帯と内側の線、翼と胴体の区切り、リベット、小物、舵面の縁取り） |
| `aircraft3.py` | デカールの置き方（`side_decal` `fin_decal` `wing_decal`）、コックピットの配色（`US_COCKPIT` `SOVIET_COCKPIT`）、MiG-21・MiG-19・F-100 の設定 |

1 機ぶんの設定例: `drafts/f_104g/f104.py`、`drafts/av_8b/paint_av8b.py`、`drafts/tu_95/paint_tu95.py`。

```
python drafts/av_8b/paint_av8b.py <入力.bbmodel> <出力.bbmodel> <シート.png>
```

道具が無い環境では 2.4・2.5 の式と以下の手順で同じことを書けばよい（必要なのは numpy と Pillow）。

### 5.2 材質を分ける

要素（キューブ）ごとに材質を決める: `skin`（外板）`glass` `frame` `interior` `seat` `dial`（計器）`mfd` `nozzle` `hole`（取り入れ口）`tyre` `hub` `strut` `tank` `missile` `pod` など。

- 手掛かりは**親グループの名前**、Blockbench の**仮色（要素の `color` 番号）**、**位置**（コックピットの箱 `|x|, y0..y1, z0..z1` の中か）
- 仮色しか無い模型では、仮色そのものが上面／下面／レドーム／ガラスの塗り分けの手掛かりになっている
- 分類を確かめるには材質ごとに 1 色で描いて見る（`bb.render_flat`）

### 5.3 UV を組む

- 全部の面に、その面だけの長方形を割り当てる（棚詰め: 高い順に並べて左から詰め、溢れたら次の段。面の間は 1 画素空ける）
- 面の大きさ（模型単位）× 密度（外板 1・ガラスと枠 2・内装 4 画素/単位）を四捨五入、最小 1 画素
- 全要素の `box_uv` を false、`autouv` を 0 にし、`uv_offset` を消す。`meta.box_uv` も false
- 各面の `texture` を 0 にする（`house.layout` は全部の面にそうするので、`null` で隠してあった面も描かれるようになる。隠したい面は後で `null` に戻す）
- `resolution` とテクスチャの `width` `height` `uv_width` `uv_height` を同じ値（例 1024）にする
- 溢れたら 2048 に上げる
- 既存の外板の UV を残して内装だけ組み直す場合は、既存の配置の右と下の空きへ詰める（面ごとの u/v の反転は保つ）

### 5.4 塗る

画素ごとに「どの面のどこか」→「世界座標 P と法線 n」→「色」の順に決める。

1. 各面の UV の長方形の画素 (X, Y) について、2.4 の式で面の上の点を出す
2. 要素と親グループの回転を掛けて世界座標 P にする（2.5）。法線も同じ回転を掛ける
3. 材質ごとの関数で色を決める。外板は:
   - 地の色（塗装の関数 `scheme(P, n, 下面か)`）
   - 構造の線: 上面・下面の面は「上から見た平面形」、胴体の横の面は「横から見た側面形」の**輪郭からの距離マップ**（1 単位格子、膨張 → 収縮で穴を埋め、収縮を繰り返して距離を数える）を引き、距離 0 を明るい帯、距離 3 を暗い線に
   - 区切りの線・リベット・小物は P の座標（|x| の帯・z のステーション）で決める。乱数を使うなら座標から作るハッシュで、区画ごとに一定にする（左右対称になるよう |x| を使う）
4. 標識を投影する（5.5）
5. ガラスと HUD 以外は不透明（アルファ 255）、ガラスの抜く所はアルファ 0
6. 使っていない領域はアルファ 0 のまま

### 5.5 標識の投影

デカール画像（RGBA、高さ h・幅 w）を、中心 o・右方向 r・上方向 u で置く。面の画素 P について

```
D = P − o
a = floor(D·r + w/2)      # 画像の列
b = floor(h/2 − D·u)      # 画像の行
```

が画像の内側で、法線の条件（例 `n.x > 0.55`）と領域の条件（例 `|x| が 6〜12 で y が 22〜41`）を満たし、画像のその画素が不透明なら、その色で置き換える。
r は 4.4 のとおり `u × n` にする。左右両側に置くなら側ごとに r を変える（片側の絵を反転して使うと鏡文字になる）。
国籍標識などの図形は 8 倍の大きさで多角形を描いてから最近傍で縮めると、ドット絵の縁になる。

### 5.6 書き戻しと確認

1. シートを PNG にして base64 で `textures[0].source` に入れ、bbmodel を保存する
2. **確認画像を出す**: 上・下・左右・斜めの 6 方向（`bb.sheet`）と、コックピットの寄り。テクセルを点で描く正投影でよい
   - 確認用レンダラは「視線が +z を向くと +x が画面の左」。これを逆にすると機番が鏡文字に見える（レンダラの間違いを塗りの間違いと取り違えない）
3. 7 章の数字を測る
4. `src/main/resources/assets/ashvehicles/bbmodel/<種類>/<id>.bbmodel` に置く
5. ゲーム内で確かめる（`gradlew runClient`。**ゲーム起動中は Gradle が動かない**）。新しい機体なら先に `gradlew runData` が通ること

## 6. よくある失敗

| 症状 | 原因 | 直し方 |
|---|---|---|
| 「同梱機らしくない」「ぼやける」 | パネルごとの色むら・まだら・グラデーション（色数 450〜700） | 区画ごとに 1 色。上位 32 色で 90% 以上に |
| 継ぎ目がノイズに見える | 継ぎ目を毎行ずらした | ずらすのはたまに 2 画素まで |
| 斜めの縁がガタガタ | 後退翼の縁に平行線を 2 本以上 | 内側の暗い線は 1 本だけ |
| 機番が読めない・星章が団子 | 回したキューブ（後退翼・傾いた尾翼）の上に 1 画素の標識 | 文字をキューブと同じだけ傾ける／その部品だけ 2 画素/単位／回っていない板へ移す |
| 一部がちらつく | 同じ面に古いキューブが重なっている（F-104G の右翼に 3 個あった） | 重なったキューブを消す |
| 文字が鏡文字 | r の向きが逆、または片側の絵を反転して使った | r = u × n |
| キャノピーが青い籠 | ガラス板の縁を全部塗った | 枠はアーチ・後端・シルだけ |
| 内装が見えない | ガラスを不透明に塗った | ガラスはアルファ 0 |
| 中から外板の柄が見える | NoCull で殻の内側にも外の柄が出る | 内側を向く面を浴槽の色に |
| 模型の向こう側が透ける（エディタ） | 縮小したシートのアルファが半端 | シートに半透明を入れない。エディタ側はミップのアルファを戻している |
| 片翼だけ柄が裏返る | box UV の `mirror_uv` の扱い | 面ごとの UV に組み直す |
| 塗ったのに古い柄のまま／ずれる | box UV の要素は面の `uv` ではなく `uv_offset` で貼られる | 面ごとの UV に組み直してから塗る |
| 2 枚目のテクスチャが出ない | GeckoLib は 1 模型 1 テクスチャ | 1 枚にまとめる |
| コックピットが 3×3 画素で何も描けない | 既定の UV が 1 画素/単位 | 内装だけ 4 画素/単位で組み直す |

## 7. 合格基準

- [ ] アルファが 0 と 255 だけ（半透明の画素 0 個）
- [ ] 上位 32 色が不透明画素の 90% 以上（色数は数百を超えない）
- [ ] 隣と色が変わる画素が 10〜25%
- [ ] パネル割りが左右対称で、機体の形に沿っている
- [ ] 標識と文字がどちら側から見ても鏡文字でなく、崩れていない
- [ ] キャノピーから内装が見える
- [ ] 確認画像 6 方向とコックピットの寄りを出して見た
- [ ] UV がシートからはみ出していない、面どうしが重なっていない

測り方（Python・numpy・Pillow）:

```python
import json, base64, io, sys
import numpy as np
from PIL import Image

d = json.load(open(sys.argv[1], encoding='utf-8'))
a = np.asarray(Image.open(io.BytesIO(base64.b64decode(
    d['textures'][0]['source'].split(',', 1)[1]))).convert('RGBA')).astype(int)
op = a[..., 3] > 127
rgb = a[..., :3][op]
_, counts = np.unique(rgb[:, 0] << 16 | rgb[:, 1] << 8 | rgb[:, 2], return_counts=True)
counts = np.sort(counts)[::-1]
both = op[:, 1:] & op[:, :-1]
diff = np.abs(a[:, 1:, :3] - a[:, :-1, :3]).sum(-1)
changed = (diff > 0) & both
print('色数', len(counts))
print('上位8色 %.1f%%  上位32色 %.1f%%' % (100 * counts[:8].sum() / counts.sum(), 100 * counts[:32].sum() / counts.sum()))
print('隣と変わる %.1f%%  差の平均 %.0f' % (100 * changed.sum() / both.sum(), diff[changed].mean()))
print('半透明の画素', int(((a[..., 3] > 0) & (a[..., 3] < 255)).sum()))
```
